This is an easy challenge from the TryHeartMe event.<br/>

First things first, let's add the server's ip to the global variables

`export IP="10.130.161.225"`

Now that this is done, let's start by launching nmap:

```bash
> nmap -sV $IP

Starting Nmap 7.98 ( [https://nmap.org](https://nmap.org) ) at 2026-03-30 18:51 +0100

Nmap scan report for website.thm (10.130.155.202)

Host is up (0.0059s latency).

Not shown: 998 closed tcp ports (conn-refused)

PORT     STATE SERVICE VERSION

22/tcp   open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.10 (Ubuntu Linux; protocol 2.0)

5000/tcp open  http    Werkzeug httpd 3.1.5 (Python 3.10.12)

Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

Service detection performed. Please report any incorrect results at [https://nmap.org/submit/](https://nmap.org/submit/) .

Nmap done: 1 IP address (1 host up) scanned in 6.42 secondsNmap done: 1 IP address (1 host up) scanned in 6.42 seconds
```

So there are two services running :

- ssh on port 22
- Werkzeug on port 5000, which is a web application library running on python.

Let's start by looking at the website on port 5000 :

By checking if any vulenrabilities exists, I found one on the version \`0.15.4\` (which is not ours).

So I continue with basic enumeration with gobuster

`> gobuster dir -w thm/SecLists-master/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://$IP:5000`

with wich I foind the /console directory but it is a dead end.

Next thing I do is check the robots.txt file (this is a file where the developers can tell to google's robots which page they do not look into).

and bingo! I get 

```plain
User-agent: *
Disallow: /cupids_secret_vault/*

# cupid_arrow_2026!!!
```

we found another directory : `/cupids_secret_vault`

By going in it, we get a little message : 

![Cupid's Secret Vault](/img/writeups/20260331-164515.png)

so again we try gobuster but on this directory

`gobuster dir -w thm/SecLists-master/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://$IP:5000/cupids_secret_vault`

and we now have a new directory : /cupids_secret_vault/administrator with a login page in it.

![login page](/img/writeups/20260331-164712.png)

So I tried with defaults credentials : admin - admin, admin - password, ... But nothing works.

I was going to try bruteforcing the form with hydra when I remembered the robots.txt file we checked earlier. It had a little comment at the end : `# cupid_arrow_2026!!!` so I try with this as a password and admin as username and BINGO the flag is ours!

![flag](/img/writeups/20260331-165054.png)


## What did I learned with this ctf : 

sometimes looking too far is not the right solution, sometimes it is under our nose since the begining!
